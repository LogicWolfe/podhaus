# MacBook Pro migration log

A running record of the effort to move Nathan's laptop role from `nb-macbook-air`
to `nb-macbook-pro`, kept to distil better configuration and a smoother
bootstrap for the next development laptop. Each entry records what was done,
what got in the way, and the improvement it suggests. The companion plan is
[macbook-pro-migration.md](macbook-pro-migration.md). When the migration ends,
the improvements below become changes to the dotfiles, Podhaus and
[MacBook setup](../macbook-setup.md), and this log is deleted.

Entry shape: date, step, what happened, friction, improvement candidate.

## 2026-11-09 first contact and investigation

| Step | What happened | Friction | Improvement candidate |
|---|---|---|---|
| SSH into the Pro | Nathan ran `ssh-copy-id` with the Air's machine public key after enabling Remote Login; the agent connects with `ssh-machine`, no 1Password needed | None; the key was in place within minutes | Document "first SSH" in MacBook setup as the step that lets an agent on the old laptop do the rest |
| Baseline the Pro | Fresh macOS 27.2, FileVault on, no Homebrew, no Xcode CLT, hostname still `Mac.localdomain` / `NB-MacBook-Pro`, `sudo` needs a password | Every root step needs Nathan at the keyboard or a password over SSH | Collect all root steps into one script Nathan runs once (hostname, CLT, Homebrew, sshd key-only) |
| Keep the Pro awake | `caffeinate -dimsu` detached over SSH | Only holds on AC power with the lid open | Add to the "before first apply" list |
| Move the machine key | Same ed25519 key copied as `~/.ssh/id_nb-macbook-pro`; every registration (Forgejo, GitHub, Pomerium, Linux hosts) keys on the public key, so none change | None | Note in Machine keys that moving a soft key between laptops is a copy plus a hostname rename |
| Map the hostname thread | 20-odd references across dotfiles and Podhaus name `nb-macbook-air` | Three dotfiles templates hard-code the hostname instead of reading a fleet flag: `lumen-enabled`, `switch-vault-enabled`, `op-vault`'s host:identity table; `docs-tunnel-update` hard-codes the 1Password field label | Drive all four from `fleet.toml` (`development`, `switch_development`) and `uname -n`, so a rename is one fleet entry plus Podhaus |
| Wi-Fi MAC | The Pro presents a private (randomised) Wi-Fi address; the Air presents its hardware MAC, which its UniFi reservation keys on | A reservation on the private MAC breaks if macOS rotates it | MacBook setup: turn off Private Wi-Fi Address for the home network before reserving |
| Probing the Pro | A read-only probe ran `python3`; without CLT, macOS pops the developer-tools install dialog on the Pro | GUI dialog on a headless step | Avoid interpreters on a fresh Mac until CLT is installed; use `sh` only |
| Herdr dependency | `run_after_16-herdr-machines-macos` calls `hc` under `set -eu`; with no Herdr.app installed the first apply aborts | Herdr.app is a direct download, not a cask, so it cannot be installed by the apply | Make the script skip with a message when `hc` is absent, like the cc-clip case should also do |
| cc-clip dependency | The setup guide already warns an apply fails without `cc-clip` because a template runs `cc-clip version` at render time | Same class as Herdr: a template-time hard dependency on a hand-installed tool | Render-time probes should degrade, not fail |
| Package script | `run_onchange_04-packages` is gated on `headless` only, not hostname; the Pro gets the full Mac set unchanged | None | Good pattern; keep gates on capabilities, not names |
| Chezmoi drift | `chezmoi status` reports `.claude/settings.json` modified, but a key-sorted comparison is identical: Claude Code rewrites the file's whitespace | False positive on every status | Have chezmoi write the file in the same formatting Claude uses, or ignore whitespace-only drift in the check |
| Running agents | Only two live sessions on the Air: this one and an idle Codex session whose work shipped; Herdr spaces live on the Linux hosts and follow the Mac automatically | None | Keeping agents on Linux hosts made the laptop swap cheap; keep it that way |
| Unpushed work | ~107 commits across 79 local branches in `hybrid-haul-truck` worktrees, 13 in `chat-investor-ui`, plus `veil-voice`, `cluster_to_23snaps`, `herdr-app` config (32 files), stashes in `SRG`, `terraform`, `terraform-sandbox-runner-auth` | A fresh clone would lose them | A periodic "unpushed work" check (fish greeting or Herdr) would surface this before a migration |
| Stale login item | Bartender 6 is a login item but is not installed | Harmless noise | Clean up on the Air; do not carry over |
| 1Password at init | `.chezmoi.toml.tmpl` bakes `has1Password` from whether the desktop agent socket exists at init time | Bootstrapping before 1Password is signed in locks in `false` until a re-init | Either install 1Password first (needs Nathan) or make the flag re-evaluated per apply |

## 2026-11-09 investigation reports

| Step | What happened | Friction | Improvement candidate |
|---|---|---|---|
| Fresh-Mac apply dry run (by reading) | Three templates (`~/.claude.json`, Zed settings, pi MCP) render through the secret runner and `node` before Homebrew's own script runs | The documented order (apply, then `op-vault mint`) cannot work; `node` is not mentioned at all | Fix MacBook setup: tokens and a temporary `node` before the first apply; or move secret-dependent renders behind a `run_after` |
| Setup guide's temporary `~/.ssh/config` | chezmoi's `create_` file never replaces an existing config and the split script refuses a file whose lines differ | Fleet SSH routing never loads on a Mac bootstrapped per the guide | Guide: never create `~/.ssh/config`; use a `config.d` fragment for the bootstrap identity |
| Clipboard tunnel script | Selects every devbox including parked quokka; an unreachable host aborts the apply and everything after it | Hidden on the Air because the script last ran when quokka was up | Skip parked hosts; consider `ssh-machine` so the script never needs 1Password |
| Claude Code on macOS | The install step is Linux-only; the README says otherwise | Manual step on every new Mac | Add a darwin branch using the official installer, or document the hand step |
| Touch ID for sudo | The always-run script aborts every apply until `/etc/pam.d/sudo_local` exists | Root step hidden inside the apply | Create it in the one-sitting root script; make the chezmoi script report rather than abort |
| `authorized_keys` on the Mac | First apply rewrites the file with only personal and devbox keys | Any key used to bootstrap the Mac is locked out mid-apply | Grant every fleet host's machine key except the host's own |
| Sessions inventory | Only two live local agents; all others on Linux hosts | None | Confirms the design: agents belong on the devboxes |
| Herdr config checkout | 32 uncommitted files from two finished Claude sessions, waiting for a human try | Work parked in a working tree nobody watches | Herdr could surface "uncommitted in a finished space" |
