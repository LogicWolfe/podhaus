Authoring a new plan

Three flavors are supported, picked by what you put in docs/plans/:

  • .md (Markdown) — easiest. Just drop the file in. The plans index links it through /plans/plan-viewer.html?file=<name>.md, which renders the Markdown client-side via the vendored marked.min.js using the same shell, theme, and TOC as the rest of the docs.
  • .html — start from docs/_template.html, add your content. The plans index links it directly. Useful when you need richer layout than Markdown gives you.
  • Directory plan — for big plans that should be split across multiple pages. Create docs/plans/<name>/ with an index.md (the landing page) plus any number of sibling .md or .html sub-pages. The sidebar shows the parent plan; sub-pages appear as indented children only when the parent or one of its sub-pages is active, so the nav stays uncluttered. See Sample Nested Plan for a worked example, including how to convert a flat plan to nested.

All flavors get the same styling. Plans don't need a fixed naming convention — descriptive kebab-case is fine.
