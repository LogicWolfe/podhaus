Structured logging across the fleet

One schema for every log row Alloy ships, on every host, documented so the next service and the next agent fit it without asking. The schema is built and described in Logging. Rows from the services that export their own telemetry (fenwick, indy-service, the book services) bypass Alloy and fit only once each sets OTEL_RESOURCE_ATTRIBUTES, below. What remains is checking the schema live, those services, delivery reliability, volume, and the decisions below.

Done so far

  • ✅ Lumen's throwaway search containers are no longer collected, stopped containers stay in discovery so a container that stops and starts again is not re-read, and Pomerium and Pocket ID ship whole bodies.
  • ✅ Volume was measured; the results are in Volume below.
  • ✅ Every row Alloy ships follows one schema. The resource carries host.name (replacing host, with the Gatus heartbeat queries rewritten to it), service.name with the host prefix stripped, service.namespace, service.instance.id and container.name; the pipeline's log attributes are log.source, log.iostream, compose.service and journal.*; loki.attribute.labels and detected_level are gone. All of it is derived in enrich.alloy, after the tailers, whose labels, relabel rules and arguments stay exactly as deployed so no saved read position is lost. enrich.alloy parses a body that is one JSON object, keeps every field under its own name except one spelled like a reserved schema name, removes every key with a credential word as any dotted part, reads a JSON level or severity field as the level, and sets the body to the message. Every parser sets severity only; Pomerium's OAuth state is removed in its own module. Tailed files carry their container's service name, compose project and compose service. Containers outside a stack are named forgejo-actions-task or unmanaged, and Lumen's index containers lumen-warm. logging/tests/ runs a captured line for every module through a real Alloy in tools/pre-commit and pins the Docker relabel rule list, the Docker tailer's arguments and every tailer's labels.
  • ✅ Severity fallback, Docker receive time and the timestamp lint, the rathole selector, JSON gates, Gatus levels, the journal audit sources, and heartbeats for bandicoot and voltaire.

Services that ship their own telemetry

fenwick, fenwick-web-agent, indy-service and the book services export OTLP themselves and never pass through Alloy. Each sets OTEL_RESOURCE_ATTRIBUTES=host.name=<host>,service.namespace=<compose project>,service.instance.id=<host>/<container name> in its compose file, in its own repository. Today none has host.name or service.namespace, and only bookcard has an instance id (a random one). mechanical

Audit trail and secrets

  • Bilby's front door logs nothing. caddy/Caddyfile has no log directive, so nothing records who reached storage.pod.haus, git.pod.haus or any public site. Turn on access logs per site with the request delete filter fractal already uses. Trade-off: volume on the public sites against having any record at all. decision
  • Pomerium runs at debug. Only ssh-auth-notify needs it, and it reads docker logs, not ClickStack. Drop DEBUG in Alloy except the keyboard-interactive line it needs. Trade-off: less to diagnose a Pomerium policy problem after the fact. decision
  • Pocket ID's query carries the OAuth state. Its request lines hold the same encrypted session blob that Pomerium's module now removes, in the query field (about 7.5k rows in 30 days). Removing it in pocket-id.alloy is a few lines, matched on the parameter as in pomerium.alloy. Trade-off: the blob is of no use to a reader and its removal costs nothing a reader needs, against one more module that edits a line. decision
  • Pomerium's callback path carries the one-time code. The sign-in callback's path includes the OAuth authorisation code. Trade-off: the code is spent within seconds of being logged, so removing it buys tidiness rather than safety, against another edit to the authentication trail's own lines. decision

Naming

  • Replica-suffixed service names. A compose service with no container_name gets Compose's generated name, so its service.name is that name less the host prefix: llm-llm-model-1 for fractal-llm-llm-model-1, whose compose service is llm-model. Using the compose service name for such containers gives short names that survive a replica count or project rename. It must be done in enrich.alloy, never by changing the tailer's service label, which keys read positions and the parsers. Trade-off: a cleaner service list, against a rename for anyone filtering on today's names and a rule that has to recognise a generated name. decision
  • llm_event duplicates event. llm-watcher.alloy copies the watcher's event field to llm_event, and the shared JSON step now ships event as well, so every watcher row carries the name twice. Dropping the copy removes a redundant attribute; nothing saved in HyperDX uses it, but the local model runbook and llm/tests name it. Trade-off: one less attribute per row, against a rename for anyone querying llm_event. decision
