Networking

One Docker bridge network, one Cloudflare Tunnel for ingress, one wildcard Access app for auth, two DNS surfaces (public Cloudflare + LAN UniFi). No nginx in the path — cloudflared talks directly to backends by container name.

dockernet bridge

Every UI-facing container joins an external bridge network called dockernet at 172.18.0.0/16. Within the bridge, containers reach each other by container name via Docker's embedded DNS — never by static IP. Static IPs are reserved for LAN devices (e.g. the UniFi gateway at 10.0.0.1) and host-network services.

Each consumer compose file declares: 

networks:
  - dockernet

# at the bottom:
networks:
  dockernet:
    external: true

Host-network services

A few services need direct host network access:

  • Home Assistant — Bluetooth, mDNS, multicast device discovery.
  • Plex — Plex's own LAN discovery protocol, GDM/DLNA.
  • Syncthing (kangaroo-side) — LAN device discovery via UDP/21027 multicast.

These declare network_mode: host in their compose. Cloudflare Tunnel reaches them via the dockernet bridge gateway IP 172.18.0.1 from cloudflared's side of the bridge — same pattern as home.pod.haus → 172.18.0.1:8123.

Cloudflare Tunnel

One deliberate exception: storage.pod.haus Every pod.haus hostname is tunnel-routed except storage.pod.haus (the public MinIO S3 endpoint). It is a grey-cloud DNS A → the kookaburra rathole relay (DigitalOcean droplet, public IP 170.64.241.136) → rathole reverse tunnel → Caddy on bilby (own LE wildcard) → MinIO. The home network has NO inbound WAN port — bilby dials out to kookaburra. The S3 data path cannot traverse Cloudflare's HTTP proxy (rewrites the SigV4-signed Accept-Encoding; single-level cert can't cover Publii vhost buckets); the rathole tunnel is raw TCP passthrough so SigV4 + Host stay intact. Full rationale + as-built: storage public ingress relay. (The earlier UniFi WAN port-forward path was replaced — the UDM Pro SE binds WAN:443 with UniFi OS itself, shadowing the forward; see minio-public-caddy.md for the historical record.)
Management plane: Tailscale (tag:podnet) Inter-host management traffic (Komodo Core→Periphery for kookaburra, log ship-back from kookaburra to bilby's ClickStack) rides a private Tailscale tailnet — bilby (bilby-podnet) and kookaburra (kookaburra-podnet). Komodo Core dials kookaburra by MagicDNS FQDN (https://kookaburra-podnet.tail9ceb.ts.net:8120 in komodo/sync/servers.toml); the IP changes on every droplet rebuild but the FQDN doesn't, so rebuilds don't require editing this config. Resolution works because bilby's /etc/docker/daemon.json sets "dns": ["100.100.100.100", "1.1.1.1"] — Docker's embedded resolver (127.0.0.11) forwards unknown names to Tailscale's MagicDNS first, then 1.1.1.1; service-name resolution (ferretdb, caddy, etc.) is still handled by the embedded resolver before forwarding. ACL is asymmetric: your devices → podnet freely; podnet ↛ your devices (blast-radius containment — a popped relay can't pivot into your laptop). The rathole data tunnel is independent (public, noise+token, NOT on the tailnet — clients reaching storage.pod.haus never touch any private network).

A single cloudflared container on bilby holds the tunnel credential. Ingress rules live in cloudflare-tunnel/config.yml (bind-mounted into the container) and look like: 

- hostname: gatus.pod.haus
  service: http://gatus:8080
- hostname: home.pod.haus
  service: http://172.18.0.1:8123

Anything not listed returns 404 at the tunnel edge. New service that needs a hostname? Add the rule here, add a cloudflare_dns_record to the relevant cloudflare/dns_*.tf file, run terraform apply from cloudflare/, then ./komodo-sync to refresh the tunnel container.

cloudflared is distroless No shell, no curl, no wget — the image only ships the cloudflared binary. In-container healthchecks against /ready on port 20241 are structurally impossible, so the stack has no healthcheck and no autoheal label. cloudflared handles its own reconnection; restart: unless-stopped catches outright crashes; external liveness is monitored by Gatus hitting the public hostnames.

Cloudflare Access

All Access applications, policies, groups, and service tokens are codified in cloudflare/access.tf (Terraform). A single Pod Haus wildcard Application covers *.pod.haus with a Family allow policy — any single-label hostname under pod.haus is gated by browser-side Cloudflare Access login automatically.

Implication for hostname design: prefer single-label names like backup.pod.haus over multi-label like backup.kangaroo.pod.haus — the wildcard only covers one label. Host-distinguishing names use a hyphen prefix instead (kangaroo-backup.pod.haus).

Every tunnel-routed pod.haus hostname has its own Access app, created by an instance of the cloudflare/modules/pod_haus_service Terraform module (one block per service in cloudflare/services_pod_haus.tf). The default policy chain is "Homelab service-token bypass → Family allow" — locked by default, overridable per service.

Per-service policy overrides currently in use:

  • UniFi — single Bypass-everyone policy (UniFi has its own LAN login).
  • Syncthing — Homelab bypass + Nathan-only reusable policy (cross-household concern, household share is private).
  • Paperless — Paperless-iOS service-token bypass at precedence 1, then the default chain.
  • Pine Lake apps — Nathan-only reusable policy, separate from the Family group (cross-household).
  • Komodo webhook — path-scoped Bypass on the komodo.pod.haus/listener/github prefix (Komodo's per-stack webhook listeners all live under it) so GitHub webhook deliveries skip Access; Komodo HMAC-validates each delivery itself.

The *.pod.haus wildcard Access app stays as the default-deny safety net. Anything not covered by a more-specific app falls through to it; the wildcard denies unless you're in the Family group or carrying the Homelab service token.

Service tokens

Two service tokens for programmatic access. Send as CF-Access-Client-Id + CF-Access-Client-Secret headers:

  • Homelab service token (op://Homelab/Cloudflare Access — Homelab Service Token) — full bypass of the *.pod.haus surface plus every per-host override above. One token, everything. Treat as high-value; a leak grants access to all of pod.haus.
  • Paperless iOS (op://Homelab/Cloudflare Access — Paperless iOS Service Token) — bypass scoped to paperless.pod.haus only. Paste both header values into Swift Paperless > Settings > Connection > Extra Headers.

DNS

All DNS is Terraform-managed under cloudflare/, state in MinIO at s3://terraform-state/cloudflare.tfstate:

  • Cloudflare public zones — per-zone dns_<zone>.tf files plus the per-service module's CNAME for each tunnel-routed pod.haus host.
  • UniFi LAN-side split-horizon — dns_unifi_split_horizon.tf declares the two A records (unifi.pod.haus → 10.0.0.1, bilby.pod.haus → 10.0.0.119) via the ubiquiti-community/unifi provider against the UniFi controller at 10.0.0.1.

Workflow: edit the relevant dns_<zone>.tf, run terraform plan from cloudflare/, then terraform apply (stock terraform, no wrapper, from any machine — creds from the chezmoi-rendered fish env). The S3 state backend is the public https://storage.pod.haus (Caddy → MinIO), not Cloudflare-proxied — see MinIO public access via Caddy + UniFi.

DNSControl (the previous DNS tool) was retired 2026-05-12; its dns/ directory, dns-preview, and dns-push scripts are gone. Provider docs (read before editing): cloudflare_dns_record, unifi_dns_record.
