Monitoring

Gatus does endpoint monitoring and pushes alerts to Postmark email. Victoria Logs + Alloy collects container logs. Grafana surfaces both. Autoheal restarts unhealthy containers locally on each host.

Gatus

Config-as-code endpoint monitoring, defined entirely in gatus/config.yaml. Monitors HTTP endpoints, pushed heartbeats, and downstream-service-state checks. Stores results in SQLite with a 90-day cap. Alerts via Postmark webhook.

Three monitor types in use:

  • HTTP — periodic GET on each *.pod.haus endpoint with status + body conditions.
  • Push (external endpoints) — bearer-token-protected URLs that jobs/scripts POST to with success=true|false&error=.... Used for Backrest nightly heartbeats and the RAR-extraction backlog scan.
  • Komodo-API check — Gatus calls Komodo Core's /read API and asserts that kangaroo's Periphery state is Ok. Surfaces "Komodo Core can't reach kangaroo Periphery" as a normal Gatus alert.

Live monitors today cover every public hostname plus the Backrest, unpackerr, and kangaroo-backrest heartbeats. gatus.pod.haus shows the live status page.

Alert body

Postmark email body is customized in gatus/config.yaml to surface, per alert: the [ALERT_DESCRIPTION] string (per-alert "what this means + where to investigate"), the failing conditions, and any [RESULT_ERRORS] from the push payload. Every alert links back to gatus.pod.haus and logs.pod.haus for triage.

Adding a Gatus monitor

Edit gatus/config.yaml — YAML anchors at the top define common defaults (interval, alert config, conditions). Append a new endpoint to the appropriate group (services / heartbeats / docker). Save. Gatus reloads config automatically on file change — no restart.

Victoria Logs + Alloy

Victoria Logs (port 9428) is the log store; logs.pod.haus serves its native vmui. Backed by /mnt/jump/victoria-logs/ on bilby; runs as 1000:100 to align with the NAS Jump squash. Retention is -retentionPeriod=180d -retention.maxDiskSpaceUsageBytes=50GB.

Grafana Alloy collectors scrape container logs from each host's Docker socket and push to Victoria Logs via the Loki-compatible push API. Two collectors:

  • bilby: logging/bilby/alloy-config.alloy — has per-container shaping (op-connect-api's log_message field and flood's msg field get rewritten to VL's expected _msg).
  • kangaroo: logging/kangaroo/alloy-config.alloy — same general shape, slightly slimmer since the bilby-specific rewrites aren't needed. Logs tagged with host="kangaroo" so they're filterable in vmui.

Grafana

Grafana lives at grafana.pod.haus. Plugged into Victoria Logs (via the victoriametrics-logs-datasource plugin) and Gatus (via the Infinity datasource hitting Gatus's API). Two dashboards provisioned via file-based config in logging/dashboards/:

  • Container Logs — VL native panel.
  • Uptime Status — Gatus endpoints via Infinity datasource. This is the home dashboard.

Grafana is intentionally stripped down: all drilldown apps disabled (Logs drilldown needs Loki's full query API which VL doesn't implement), alerting disabled (Gatus owns it), news feed off, plugin marketplace hidden.

Autoheal

Each host runs its own autoheal container (willfarrell/autoheal) — bilby's autoheal can't see kangaroo's Docker daemon, so each Periphery host needs one. Autoheal watches the local Docker daemon and restarts any container whose healthcheck reports unhealthy for ~3 consecutive checks, provided the container has the autoheal: "true" label.

Standard pattern on every healthy stack: 

services:
  my-service:
    ...
    labels:
      autoheal: "true"
    healthcheck:
      test: ["CMD-SHELL", "..."]
      interval: 60s
      timeout: 10s
      retries: 3
      start_period: 30s

Alerting flow

  1. Endpoint check fails (HTTP non-2xx, body assertion fails, push missing, etc.).
  2. After failure-threshold consecutive failures (typically 3), Gatus fires the alert chain.
  3. Postmark webhook sends email from alerts@pod.haus with the rich body.
  4. Recovery (3 consecutive successes) sends a resolution email.
