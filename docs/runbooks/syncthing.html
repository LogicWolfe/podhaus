Syncthing

Runs on kangaroo. Host network provides LAN device discovery via UDP/21027 multicast. UI exposed at sync.pod.haus through the bilby Cloudflare Tunnel, currently routed to 10.0.0.25:8384. GUI auth is disabled; Cloudflare Access is the gate externally.

Why it lives on kangaroo

Syncthing's main shared folder is Pouch (the QNAP HDD array). Running Syncthing on kangaroo keeps file scanning, hashing, and sync on local storage instead of NFS.

Kangaroo's device ID

Kangaroo's Syncthing came up with a fresh device ID during the relocation: 

J7Z7LNA-U65UY7V-C7BTJXK-XBOON5E-5UAZBXM-KOXNWRP-DBOIFEL-DCXTEQD

Peer devices (phone, laptop, etc.) must be paired with this ID — the old bilby-side device ID is dead. ~2 minutes per peer in the Syncthing UI. After re-pairing, folder shares need to be accepted in each peer's UI as well; the existing .stignore patterns at the root of each shared folder are picked up automatically.

The Pouch .stignore (mixed-source)

Pouch's .stignore is structured as an allow-list: top-level dirs are ignored by default, then specific !TV/<Show>, !Movies/<Title>, !Kids/... entries opt items back in (the trailing ** at the end of the file ignores everything else not matched). Inside each !<TopLevel>/ block, entries are sorted case-insensitively.

Entries come from two sources:

  • Hand-curated — the bulk of the file. Edited directly on /share/CACHEDEV1_DATA/Pouch/.stignore (or any peer's view via the syncthing folder root).
  • Auto-injected by flood — torrents tagged pinelake in Flood get a !${base_path#/data/} line written here on completion. Driven by flood/scripts/pinelake-stignore.sh (see the flood runbook). The script writes across NFS from bilby into Pouch — kangaroo's syncthing reads the change locally and rescans.

The two sources share the file without sentinels: the reconciler is insert-only and idempotent, so a hand-curated entry that happens to match a tagged-torrent entry is harmless. Removals are always manual.

GUI auth is intentionally off — silence the warning the right way We run the GUI open (no user/password): externally gated by Cloudflare Access, LAN trusted. Syncthing then shows a red "remote access without a password" banner. That banner is not a dismissible notification — it's a live openNoAuth check recomputed every page load, so clicking the × or acking authenticationUserAndPassword does nothing. The only lever is gui.insecureAdminAccess=true (per the source comment, "the magic setting to silence the warning"). It changes no access behaviour — the GUI is already open without it; it only flips the banner off and adds one startup log line. Set it without restoring a fresh-rebuild config via: 
curl -s -X PATCH -H "X-API-Key: $(grep -oP '(?<=<apikey>)[^<]+' config.xml)" \
  -d '{"insecureAdminAccess":true}' http://10.0.0.25:8384/rest/config/gui
It persists in config.xml (backed up), but a fresh-identity rebuild resets it — re-apply the one PATCH. There is no Syncthing env var for it, so it can't be baked into compose.

Permissions

Container runs as 1000:100 (PodHaus:everyone) to match existing file ownership on the Pouch share. The .stignore file is owned 1000:100 so reads and writes are permission-clean.

First-run chown On first deploy the config dir gets auto-created by Docker as admin:administrators when the bind source doesn't exist. Syncthing (running as 1000:100) can't write its autogenerated cert/key in that dir. Fix: 
sudo chown -R 1000:100 /share/CACHEDEV2_DATA/Container/syncthing-config
once, then restart the container. Won't recur after the first boot.

Performance notes

Initial-hash performance measured at ~42 MB/s on the GX-420MC at startup. First scan of the 30 TB Pouch share is a long run (~40h+ on cold hashes) but steady-state delta-sync is fast.

Ingress

Terraform-managed Cloudflare Tunnel rule: 

sync.pod.haus → http://${local.kangaroo_active_ip}:8384
local.kangaroo_active_ip = 10.0.0.25

bilby's cloudflared routes over the LAN to kangaroo's published port. The active NIC is a single Terraform knob in terraform/services_pod_haus.tf; 10.0.0.232 remains the spare 1GbE path.
