Plex

Runs on bilby with network_mode: host. Library DB lives on local NVMe while media and BIFs live on Pouch. Identity is templated from Preferences.xml in the repo + a Plex Online Token from 1P, so a host wipe doesn't lose either identity identifier.

Critical identity state

The preferences contain both MachineIdentifier (the raw serial) and ProcessedMachineIdentifier (the client identifier exposed by the local API and plex.tv). The official Plex container derives the latter from the former when it is absent, then sends the processed value as X-Plex-Client-Identifier. Preserve and verify both. Losing or replacing the externally registered processed ID makes clients see a different server; preserving only a plausible-looking raw value is not an identity proof.

The init container in plex/compose.yaml merges the template's enforced attrs (identity, network prefs) into the live Preferences.xml on each deploy. Plex's own runtime can mutate other prefs in that file freely; the next deploy re-enforces the identity attrs.

A template is not sufficient evidence

Before an identity-sensitive migration, capture the raw ID, processed ID, anonymous ID, certificate UUID, token fingerprint, local API identity, and plex.tv resource. Verify the same set after startup. Pine Lake proved why this matters: its raw ID is a UUID while its externally visible processed ID is a different 40-character digest. Never copy Bilby's values to another server or replace one field with the other.

Pinelake identity

Pinelake runs pinelake-plex under OrbStack. Its state lives at /Users/Shared/Podhaus/plex, and its required identity is committed in ansible/roles/pinelake_macos/files/plex-identity.json. The stack's preference initializer enforces all four identity fields and injects the existing Plex token from the pinelake-plex Homelab item.

Every deployment first validates the TerraMaster mounts and the identity manifest. Replacing a running server requires two successful zero-session checks; recovery is allowed only when no Plex process or port 32400 listener exists. Plex is deliberately excluded from generic Autoheal so an automated restart cannot bypass that gate.

Pinelake enforces bilby's preference set with two deliberate differences, both forced by the platform. OrbStack has no bridged networking mode, so a container can only ever see the virtual machine's namespace: Plex enumerates OrbStack bridge addresses and never finds the Mac's LAN address that same-house clients need. The plex-advertise launch daemon closes that gap. It reads en0, compares the result with the live customConnections preference, and writes through PUT /:/prefs only when the two differ — no restart, no redeploy. The address is a DHCP lease, so this runs on a timer rather than at deploy time; a value written once goes stale on its own. It publishes the literal address first and the Mac's Bonjour name second, the latter being an independent fallback that tracks DHCP without the daemon.

customConnections is therefore absent from Pinelake's Preferences.xml.tmpl, and must stay absent. plex-preferences.py merges rather than replaces, so naming the attribute there would overwrite the daemon's value on every deploy.

The second difference is ManualPortMappingMode="0". Pine Lake is behind Starlink CGNAT with no inbound path over either IPv4 or IPv6, so no port mapping can exist and Plex falls to its own relay for remote clients. Because every stack shares one runtime, Plex runs on a published port rather than host networking: host mode there would make it advertise every stack's bridge as a reachable address, a list that grows with each new Pinelake stack.

Web ingress

plex.pod.haus routes through Numbat Pomerium and the private rathole origin to Caddy, which reaches http://172.18.0.1:32400. Plex runs network_mode: host, so dockernet's bridge gateway IP is Caddy's entry point.

Web-only. Native Plex clients are not told about this URL via customConnections — they continue to use plex.tv discovery (LAN, direct WAN, Plex Relay). Avoids duplicate-server confusion in client UI.

plex.pinelake.haus is the same arrangement for Pine Lake, reached through the shared pinelake_http rathole service and Pinelake's own Caddy, which resolves pinelake-plex over dockernet. The same web-only rule applies, and matters more there: Pine Lake's advertised list carries LAN addresses only, so no client can be handed a path that leaves the house. Numbat carries Pine Lake's SSH, logs and browser routes — never its video.

Remote access (the three settings)

Three preferences must be set in Preferences.xml for remote access to work. All three are in the templated identity attrs, so they survive rebuilds.

SettingValueWhy
PublishServerOnPlexOnlineKey1The master "Enable Remote Access" toggle. When 0, Plex doesn't run its publish flow at all.
ManualPortMappingMode1Tells Plex "skip UPnP, trust the static port forward". Needed because UniFi silently drops the UPnP SSDP multicast Plex uses for auto-mapping.
ManualPortMappingPort32400External port the UniFi port forward points at.

Verifying remote access

TOKEN=$(docker exec plex sh -c \
  'grep -oE "PlexOnlineToken=\"[^\"]*\"" \
   "/config/Library/Application Support/Plex Media Server/Preferences.xml" \
   | cut -d\" -f2')

curl -s "http://localhost:32400/myplex/account?X-Plex-Token=$TOKEN" \
  | grep -oE '(mappingState|publicAddress|publicPort)="[^"]*"'

Must show mappingState="mapped", a non-empty publicAddress, and a real publicPort. If publicAddress="" or publicPort="0", the publish loop is broken — start with PublishServerOnPlexOnlineKey.

LG webOS plays the wrong audio (multi-track files)

Symptom. On the LG TVs a title plays a non-English audio track, and no track in the picker produces English. The same file is fine on iOS, web and desktop. Forcing a transcode (turn off Direct Play, or drop quality off "Original") plays English correctly. Only a small percentage of titles are affected.

Cause. Under Direct Play, Plex hands the TV the original file and the TV does its own audio-track selection. webOS mishandles that selection on files with a large number of audio tracks, so the client's choice never reaches the demuxer. Transcoding works precisely because the server does the selection and emits one audio stream. Affected files are typically Disney+ MULTi rips carrying 15–25 audio tracks.

Two red herrings

These releases often order English [Audio Description] before the real English track, and often flag no audio track as default. Neither is the cause — removing the AD track or fixing the default flag does not fix it. Nor is it the codec; the AAC tracks decode fine. Track count is the trigger.

Fix. Remux the file down to a single English audio track. There is then nothing to select and no index to miscount. Block copy, no re-encode, seconds per file; Dolby Vision RPU and HDR metadata ride in the HEVC bitstream and survive untouched. Leave subtitles alone unless there's separate evidence they're involved.

Identify the real English track — not the [Audio Description] one — and note its id: 

mkvmerge -J file.mkv | jq -r '.tracks[] | select(.type=="audio")
  | "\(.id) \(.properties.language) \(.properties.track_name)"'

Then remux in place, substituting that id in all four places. The .tmp extension keeps Plex's scanner off the partial file: 

mkvmerge -q -o "$f.tmp" \
  --audio-tracks 4 \
  --default-track-flag 4:yes \
  --forced-display-flag 4:no \
  --track-name 4:"English" \
  "$f"
mv -f "$f.tmp" "$f"

Verify each output before replacing the original — exactly one audio track, language eng, video track present, DV state matching the source, and duration matching the source. Abort the batch on any mismatch rather than continuing: 

mkvmerge -J out.mkv | jq '[.tracks[] | select(.type=="audio")] | length'   # must be 1
ffprobe -v error -select_streams v:0 \
  -show_entries stream_side_data=dv_profile -of csv=p=0 out.mkv          # same as source

Compare DV to the source, don't assert it

Scene releases are not internally consistent: in the Maul season only E01, E08 and E10 carry a DOVI configuration record at all, the rest are plain HDR10, despite HDR DV in the release name. A verify step that asserts "DV must be present" will false-fail on the majority of the season. mkvmerge itself preserves DV correctly (confirmed on E01) — assert output DV == input DV.

To confirm the surviving track is the real English mix and not the AD one, decode the same window from the source track and the remuxed track and compare volumedetect histograms — identical buckets means the right track survived: 

ffmpeg -nostdin -ss 300 -t 120 -i file.mkv -map 0:a:<n> -af volumedetect -f null - 2>&1 \
  | grep -E 'histogram_[678]db|max_volume'

Afterwards run a library scan plus Analyze on the show so Plex re-reads the stream list. Any stored per-item audio-stream selection becomes moot once there is only one track.

Known affected. Star Wars: Maul — Shadow Lord S01 (17 audio tracks, remuxed 2026-07-25) and DuckTales (1987) (23 audio tracks). Both under Pouch. If a third title turns up, the layout signature to look for is a double-digit audio-track count on a MULTi release.

Monthly stats cleanup

Plex's statistics_bandwidth table grows indefinitely with no upstream pruning mechanism. Left unchecked it can balloon the DB by tens of GB. An ofelia job runs an online DELETE + VACUUM on the 1st of each month at 05:30 AWST via plex/scripts/stats-cleanup.sh. See Plex maintenance log for the historical incident that prompted this.

Why the DB is on local NVMe (not NFS)

Pre-Phase-6, Plex's DB lived on Jump over NFS. SQLite on NFS under write contention (butler scans, normal play state updates) cascaded into lock storms that surfaced as client-visible stalls. Moving the DB onto bilby's NVMe eliminated the contention class entirely. Bulk media reads stay on Pouch (sequential, HDDs are fine).

No hardware transcoding

Apple Silicon's VideoToolbox media engines have no Linux driver — they're an undocumented Apple block, Asahi can't expose them. Plex transcoding is software-only. M1 CPU is fast enough for 1080p in software trivially; 4K HDR tone-mapping is the worst case, and the answer there is "play a different copy" or "let the client direct-play".
