Plex

Runs on bilby with network_mode: host. Library DB lives on local NVMe (post-Phase-6 pivot); media and BIFs live on Pouch. Identity is templated from Preferences.xml in the repo + a Plex Online Token from 1P, so a host wipe doesn't lose the MachineIdentifier.

Critical identity state

Clients (apps, smart TVs, plex.tv) identify the server by its MachineIdentifier. If it changes, every client treats it as a new server — shared libraries break, watch state is orphaned, every device must re-pair.

FieldSource of truth
MachineIdentifierplex/Preferences.xml in repo (template)
CertificateUUIDplex/Preferences.xml in repo (template)
AnonymousMachineIdentifierplex/Preferences.xml in repo (template)
PlexOnlineUsernameplex/Preferences.xml in repo (template)

Server name (hostname)plex compose hostname: Bilby

The init container in plex/compose.yaml merges the template's enforced attrs (identity, network prefs) into the live Preferences.xml on each deploy. Plex's own runtime can mutate other prefs in that file freely; the next deploy re-enforces the identity attrs.

Library paths are stored as absolute paths in the SQLite DB. Mounting Pouch at the same path inside the container that the DB expects means zero library reconfiguration after a host rebuild.

Web ingress

plex.pod.haus routes to http://172.18.0.1:32400 via Cloudflare Tunnel (Plex runs network_mode: host, so dockernet's bridge gateway IP is the entry point).

Web-only. Native Plex clients are not told about this URL via customConnections — they continue to use plex.tv discovery (LAN, direct WAN, Plex Relay). Avoids duplicate-server confusion in client UI.

Remote access (the three settings)

Three preferences must be set in Preferences.xml for remote access to work. All three are in the templated identity attrs, so they survive rebuilds.

SettingValueWhy
PublishServerOnPlexOnlineKey1The master "Enable Remote Access" toggle. When 0, Plex doesn't run its publish flow at all.
ManualPortMappingMode1Tells Plex "skip UPnP, trust the static port forward". Needed because UniFi silently drops the UPnP SSDP multicast Plex uses for auto-mapping.
ManualPortMappingPort32400External port the UniFi port forward points at.

Verifying remote access

TOKEN=$(docker exec plex sh -c \
  'grep -oE "PlexOnlineToken=\"[^\"]*\"" \
   "/config/Library/Application Support/Plex Media Server/Preferences.xml" \
   | cut -d\" -f2')

curl -s "http://localhost:32400/myplex/account?X-Plex-Token=$TOKEN" \
  | grep -oE '(mappingState|publicAddress|publicPort)="[^"]*"'

Must show mappingState="mapped", a non-empty publicAddress, and a real publicPort. If publicAddress="" or publicPort="0", the publish loop is broken — start with PublishServerOnPlexOnlineKey.

Monthly stats cleanup

Plex's statistics_bandwidth table grows indefinitely with no upstream pruning mechanism. Left unchecked it can balloon the DB by tens of GB. An ofelia job runs an online DELETE + VACUUM on the 1st of each month at 04:00 AWST via plex/scripts/stats-cleanup.sh. See Plex maintenance log for the historical incident that prompted this.

Why the DB is on local NVMe (not NFS)

Pre-Phase-6, Plex's DB lived on Jump over NFS. SQLite on NFS under write contention (butler scans, normal play state updates) cascaded into lock storms that surfaced as client-visible stalls. Moving the DB onto bilby's NVMe eliminated the contention class entirely. Bulk media reads stay on Pouch (sequential, HDDs are fine).

No hardware transcoding Apple Silicon's VideoToolbox media engines have no Linux driver — they're an undocumented Apple block, Asahi can't expose them. Plex transcoding is software-only. M1 CPU is fast enough for 1080p in software trivially; 4K HDR tone-mapping is the worst case, and the answer there is "play a different copy" or "let the client direct-play".
