Hosts

Seven active hosts. Bandicoot's Komodo Core manages bilby, kangaroo, Numbat, fractal, voltaire, bandicoot, and pinelake.

bilby

Apple M1 Mac mini, 8 cores, 15 GB RAM, aarch64, Fedora Asahi Linux. Primary host. Runs the primary podhaus stacks and an outbound Komodo Periphery. LAN IP 10.0.0.119. Komodo Core and 1Password Connect moved to bandicoot on 2026-09-09.

Its docs-server instance is reachable both at the shared docs.pod.haus and at its own per-host name, bilby.docs.pod.haus — the same container, just a second Pomerium route and a second Caddy Host match. See Networking → current ingress rules.

Filesystem highlights:

  • Local NVMe — hot operational state for every stack. See Storage for the per-stack layout.
  • /mnt/pouch: NFS mount of the QNAP HDD array. Plex media and Flood downloads.
  • /mnt/jump: NFS mount of the QNAP SSD array. Restic repositories, Paperless documents, Forgejo data, and Plex BIF thumbnails.

SELinux on Fedora Asahi

Most container bind mounts need security_opt: label=disable or the :z volume flag. Pattern documented in Stack conventions.

Host CLI tools

For ad-hoc debugging and one-shot administration of containerized services, install the service's client CLI on bilby rather than spinning up a throwaway container or docker exec-ing into the running stack. Host-installed clients give you tab completion, persistent history, scriptable composition, and don't depend on whether the target container has the right tooling shipped inside.

The container approach still wins for two narrow cases: (a) one-time bootstrap of a stack you don't expect to interact with again, and (b) reaching a service whose protocol isn't routable from the host (rare — most run on dockernet, reachable from the host via the bridge gateway at 172.18.0.1). Everything else: install locally.

Firewall (firewalld)

bilby runs firewalld. The source of truth is the firewalld Ansible role — ansible/roles/firewalld/files/zones/public.xml (the LAN-facing end0 zone) plus files/services/*.xml (custom port groups). The role installs the service XML first, then the zone, runs firewall-cmd --check-config, and only then reloads. To change the firewall: edit the XML under ansible/roles/firewalld/files/ and run ansible-playbook playbooks/bilby.yml --tags firewall from ansible/.

Never edit the firewall imperatively

Do not use firewall-cmd --add-port/--add-service (even --permanent). That writes straight to /etc/firewalld/ and diverges from the role's files; the next playbook run silently overwrites and reverts it. Change the XML, re-run the play.

The public zone allows ssh, mdns, dhcpv6-client, plex, and music-assistant, plus a rich rule that trusts the entire home LAN (10.0.0.0/24 → accept). Two patterns follow from that:

  • LAN-only service → no explicit rule. Anything reached only by devices on 10.0.0.0/24 is already covered by the LAN trust rule. Example: Home Assistant's HomeKit bridge on tcp/21063, reached only by the LAN Apple hubs (its advertise_ip is pinned to the IPv4 LAN address). Adding an explicit service for it would needlessly expose the port to the tailnet and dockernet.
  • Service needing non-LAN reach → explicit service XML. plex and music-assistant get their own XML because Caddy reaches them via the dockernet gateway (172.18.0.1, not in 10.0.0.0/24). That inbound flow isn't covered by the LAN rule, so the port must be named explicitly.

kangaroo

QNAP NAS, AMD GX-420MC, 16 GB RAM, QTS 5.x with Container Station, ext4. Secondary host. Runs a Komodo Periphery agent + Syncthing + a second Backrest + autoheal + a logging Alloy collector + the Pouch-backed RustFS instance. The active 10GbE LAN IP is 10.0.0.25; 10.0.0.232 is the spare 1GbE path.

Filesystem highlights:

  • /share/CACHEDEV1_DATA/Pouch — the bulk HDD volume. Same content bilby sees as /mnt/pouch. The dedicated RustFS data root is /share/CACHEDEV1_DATA/Pouch/rustfs.
  • /share/CACHEDEV2_DATA/Jump — the SSD volume. Kangaroo's Backrest restic repo lives at /share/CACHEDEV2_DATA/Jump/backups-kangaroo — a separate repo from bilby's to avoid restic two-client coordination.
  • /share/CACHEDEV2_DATA/Container/komodo-periphery/etc-komodo/ — Periphery state.

No Container Station GUI involvement

The bootstrap uses SSH to install and start Periphery. After that, Periphery deploys stacks through the QNAP Docker socket. Container Station's REST API only accepts built-in template names, and its GUI flow blocks the docker.sock mount Periphery needs. Survival across CS/QTS upgrades is handled by the QNAP boot-DOM autorun.sh installed from kangaroo/host-autorun/. It starts Container Station's user Docker engine and reconciles exited or detached containers. See disaster recovery.

fractal

Fedora 44 under WSL2 on a Windows desktop. Ryzen 9 9950X3D, 32 vCPU, a 25 GB memory limit for the guest, 1 TB ext4 root plus a LUKS /home. The memory limit is set in a Windows-side WSL configuration file that Ansible cannot reach, so it is changed on the Windows desktop. The GPU, an RTX 5090, belongs to Windows, which exposes it to the guest. It is two things at once: Nathan's remote development machine and an ordinary podhaus host. The first host provisioned entirely by Ansible — it has no bootstrap script and never had one.

Almost everything in and out is a connection fractal makes. WSL runs in mirrored networking mode, so the guest shares the Windows host's LAN address 10.0.0.70, UniFi-reserved so it cannot drift. Windows' Hyper-V firewall for WSL admits two inbound paths from the home network and nothing else: SSH on :22, and the model service's Fenwick listener on :8086, where Caddy admits only bandicoot. A split-horizon fractal.pod.haus A record (Terraform, UniFi resolver) points at that address, for SSH and for Fenwick's calls to the model. That keeps fractal reachable from the home network — including for bilby-resident agents — even when the Pomerium edge is down. It is safe where a kangaroo split record would not be, because no HTTPS is served at this name: fractal's HTTPS name fractal.docs.pod.haus is separate and stays on Pomerium.

Windows-side settings. Ansible cannot reach Windows, so these are set by hand on the desktop and recorded here. The guest's memory limit and networkingMode=mirrored are in the [wsl2] section of %UserProfile%\.wslconfig; a change takes effect after wsl --shutdown. Mirrored networking and the Hyper-V firewall need Windows 11 22H2 or later and WSL 2 from the Store (wsl --version); on anything older WSL ignores the setting and stays on NAT. There is no netsh interface portproxy forward: under mirrored networking a Windows listener on :22 would take the port from the guest's sshd. The firewall rules, from an elevated PowerShell (the GUID is WSL's Hyper-V VM creator id, which Get-NetFirewallHyperVVMCreator lists): 

$wsl = '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}'
New-NetFirewallHyperVRule -Name podhaus-ssh -DisplayName 'podhaus: LAN SSH' `
  -Direction Inbound -VMCreatorId $wsl -Protocol TCP -LocalPorts 22 `
  -RemoteAddresses 10.0.0.0/24 -Action Allow
New-NetFirewallHyperVRule -Name podhaus-llm-fenwick -DisplayName 'podhaus: model service for Fenwick' `
  -Direction Inbound -VMCreatorId $wsl -Protocol TCP -LocalPorts 8086 `
  -RemoteAddresses 10.0.0.0/24 -Action Allow

The rules are the only way in because the WSL firewall's default for incoming traffic is Block, Windows' own default. Under mirrored networking anything else listening in the guest, Docker's published ports included, would otherwise be open to the LAN. Get-NetFirewallHyperVVMSetting -PolicyStore ActiveStore -Name $wsl shows DefaultInboundAction : Block.

  • Ansible-managed (root state): hostname via /etc/wsl.conf, timezone (the clock itself is Windows'), Docker CE + dockernet, NVIDIA's container toolkit and Docker runtime so containers can use the GPU (no Linux driver; see Host provisioning), the developer toolchain, docs source slots, the Pomerium SSH user-CA trust, and Komodo Periphery. Run ansible/playbooks/fractal.yml.
  • chezmoi-managed (user state): everything under $HOME — shell, dotfiles, the machine SSH key. Applied by Nathan as himself; Ansible never invokes it.
  • Komodo-managed: fractal-relay (rathole client), fractal-caddy (mTLS origin), fractal-logging (Alloy), fractal-llm (the local model service), and fractal-docs (the docs-server over its Ansible-exposed repository sources) through linked repos podhaus-fractal and docs-server-fractal.
  • Bootstrap-managed: Komodo Periphery only — Core reaches this host solely through the connection Periphery makes, so a Komodo-driven redeploy of it would sever the path it runs on. Same reasoning as kangaroo. Ansible owns it instead of a script.

Time sync. Windows owns the clock. The guest shares one kernel clock with WSL's own system distribution, and WSL keeps that clock on Windows time: a chronyd belonging to WSL's own system distribution, not this one, steers the shared clock to the Windows clock (/dev/ptp_hyperv), and Hyper-V's time sync sets the guest from Windows again at every start and resume and whenever it falls 5 seconds or more behind. No NTP daemon runs in this distribution: a second one would steer the same clock against WSL's, so the wsl role removes chrony wherever it is installed. The guest is therefore exactly as right as Windows Time.

Windows Time is configured by hand on the desktop, so it is recorded here. It is an NTP client of time.cloudflare.com, 0.pool.ntp.org and 1.pool.ntp.org, each flagged 0x8 for client mode (a bare name is queried in symmetric mode, which a time server does not expect), polling every 64 to 1024 seconds, and its service starts automatically rather than on demand. From an elevated PowerShell: 

Set-Service w32time -StartupType Automatic
Start-Service w32time
$config = 'HKLM:\SYSTEM\CurrentControlSet\Services\W32Time\Config'
Set-ItemProperty $config -Name MinPollInterval -Value 6
Set-ItemProperty $config -Name MaxPollInterval -Value 10
w32tm /config /syncfromflags:manual /manualpeerlist:"time.cloudflare.com,0x8 0.pool.ntp.org,0x8 1.pool.ntp.org,0x8" /update
w32tm /resync

To check it, w32tm /query /status names one of those servers as its source, never Local CMOS Clock, and the stripchart measures Windows against Cloudflare directly; a healthy offset is a few tens of milliseconds: 

w32tm /query /status
w32tm /stripchart /computer:time.cloudflare.com /samples:5 /dataonly

From inside the guest, compare its clock with the same server. Fedora ships python3 but no NTP query tool once chrony is gone, so this one asks Cloudflare directly and signs the result the way the stripchart does (server minus local, so negative means ahead). It should print about the stripchart's offset, sign included: a guest that disagrees with Windows points at WSL's sync, and both being wrong points at Windows Time. 

python3 -c 'import socket, struct, time
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM); s.settimeout(5)
s.connect(("time.cloudflare.com", 123))
t1 = time.time(); s.send(b"\x23" + 47 * b"\0"); reply = s.recv(48); t4 = time.time()
t2, t3 = (sec - 2208988800 + frac / 2**32 for sec, frac in (struct.unpack("!II", reply[i:i + 8]) for i in (32, 40)))
print(f"time.cloudflare.com minus guest: {((t2 - t1) + (t3 - t4)) / 2 * 1000:+.1f} ms")'

Ingress is an outbound rathole client to numbat, following the same pattern as bilby: fractal.docs.pod.haus lands on Pomerium, which forwards to 127.0.0.1:8444 on numbat, through the tunnel to fractal's Caddy on :4443 (mTLS origin), and on to the docs container; llm.pod.haus takes the same tunnel to the model service. Off-LAN SSH takes the same route via 127.0.0.1:2204 and the ssh://fractal Pomerium route through a chezmoi Match originalhost rewrite; on the home network a preceding localnetwork match connects direct via the split-horizon record instead. Alloy ships logs across the home LAN in plaintext to the ClickStack collector's published port on bandicoot, as bilby and kangaroo do.

Local model service. fractal-llm (llm/) runs a llama.cpp server on the GPU, a one-shot job that downloads and checksums the model file, and a watcher that unloads the model when a Windows game wants the GPU and loads it again when the GPU has been quiet. The server and the watcher carry a Compose GPU request (driver: nvidia). The same Caddy that fronts the docs server serves it at llm.pod.haus through Pomerium, on a loopback-only port, 127.0.0.1:8085, for callers on fractal, and on :8086 for Fenwick on bandicoot, which Caddy limits to bandicoot's address. Every container has a memory limit, and the server's oom_score_adj makes it the first process killed if the guest runs out of memory. The model file lives in the llm-models volume on the root filesystem, which is re-downloadable and not backed up. See the local model runbook.

fractal has no backup stack. Everything Ansible and chezmoi put there is reproducible from the repos, and its Periphery private key also exists on bandicoot under /opt/komodo/keys/. The one category that is not covered is uncommitted work in ~/repos — that is a developer-discipline boundary today, not a backed-up one. Revisit if anything else lands on the host.

There is no TPM and no USB passthrough under WSL, so fractal cannot hold a hardware-resident machine key the way voltaire (TPM), bilby and bandicoot (YubiKey PIV) do. Its machine key is a soft ed25519 key on the LUKS /home. A YubiKey was considered and rejected: usbipd attach is manual and does not survive a reboot, which forfeits the unattended-agent property the key exists for and deepens exactly the Windows coupling the outbound-only design avoids.

MeTube lets anyone in the family paste a video, playlist, or channel URL at metube.pod.haus — the front door is bilby's Caddy behind a Pomerium family route — and have the result land on Pouch under Kids/ (AV1 preferred, MP4 + AAC, thumbnails embedded) for Plex to pick up. The web UI itself is LAN-only, at 10.0.0.90:8081; scratch space and queue state live under /var/lib/metube on local NVMe.

It is a laptop, so the base role's podhaus_is_laptop policy keeps it on the network: a logind drop-in ignores the lid switch and idle, and every sleep target is masked so the GNOME session cannot suspend it either. Power draw with the lid shut is the accepted cost.

GNOME runs only while there is a display to show it on. The gnome_on_demand role boots the host to multi-user.target with gdm.service disabled, and a policy script (podhaus-desktop-policy) is GDM's only starter. A display is present when the lid is open or any non-panel DRM connector is connected. A lid watcher subscribes to logind's LidClosed property and a udev rule on drm change events both re-run the policy; when a display appears it starts GDM (greeter, no autologin) and disarms the stop timer, and when the last display goes it arms podhaus-desktop-stop.timer (gnome_on_demand_stop_after, default one hour). When the timer fires the policy re-checks, stops GDM and terminates any remaining seat0 graphical session. Anything left open in the desktop dies with it; there is no warning. SSH sessions, the user manager and the machine SSH agent are unaffected because the user lingers.

Its machine key is hardware-resident on a YubiKey PIV slot, exactly as bilby's is; /home is an unencrypted Btrfs subvolume, also as on bilby, so the secret material on disk is the op-vault token file and the PIV PIN in ~/.config/machine-ssh/pin — the PIN's only copy anywhere, inert without the token, and replaceable by minting a new key if lost. SELinux is enforcing (Fedora Workstation default), so every bind-mounting service carries security_opt: [label=disable]. Fedora's preinstalled Toolbox went with podman: Docker is the single container engine.

Backup: bandicoot-backup (backup/bandicoot) snapshots the state of services that live here to a restic repository on Jump (/mnt/jump/backups-bandicoot), Jump-sentinel-gated like bilby's; that covers the ClickStack mongo dumps, Komodo's Postgres/FerretDB, the 1Password Connect data volume, MeTube's queue state under /var/lib/metube/state (its downloaded media on Pouch is not backed up), Sonarr's state, RustFS, the Fenwick bot's SQLite and the Signal device link, and the book services' state (/var/lib/bookcard less its downloads and source archives, /var/lib/bookshelf). Bilby's nightly Backrest hook copies these snapshots into its own repository, which it mirrors to OneDrive — see Backup & recovery.

Adding another host

Any host that can run Python: use Ansible. fractal is the worked example — see Host provisioning for the role layout and the chezmoi boundary. In outline:

  1. Add the host to ansible/inventory/hosts.yml and give it an inventory/host_vars/<host>.yml. Put it in the role groups it belongs to (docker_hosts, komodo_periphery_hosts, devboxes).
  2. Generate its X25519 Periphery keypair on bandicoot, drop the pubkey at komodo/keys/<host>-periphery.pub, and append file:/config/keys/<host>-periphery.pub to KOMODO_PERIPHERY_PUBLIC_KEYS in komodo/compose.env. Never commit the private half.
  3. Declare the Server in komodo/sync/servers.toml with address = "" (new Peripheries dial Core outbound) and a Linked Repo in komodo/sync/repos.toml. Use files_on_host only if the repo will live directly on the host, bilby-style.
  4. Write <host>/periphery/compose.yaml and run the playbook. The komodo_periphery role ships the keys, brings the container up, and blocks until Core reports the Server Ok.
  5. Add the host's per-host overlays to backup/, autoheal/, logging/ following the existing pattern.

kangaroo is the exception and stays script-provisioned: QTS ships no Python at all, so it can never be an Ansible target. kangaroo_bootstrap remains its runbook.
